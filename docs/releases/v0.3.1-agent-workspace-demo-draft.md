# v0.3.1 - Harness 与本地知识栈闭环版

> 正式发布说明，可直接用于 GitHub Release。

## Summary

`v0.3.1` 在正式平台宿主完成命名收口后，补齐两条工程主线：默认本地知识栈和可信 AI 变更闭环。

本版本将 LightRAG 作为 repo-local 服务接入默认启动链路，同时让 Harness 负责路由与治理、OpenSpec 负责持久变更生命周期，并通过验证证据和 CI 阻断非法完成状态。

## Highlights

- repo-local LightRAG HTTP 与项目级 MCP 知识链路进入默认本地栈
- Harness 活动 helper host 从 `.omx` 收敛到 `.harness`
- B1/B2/B3 与 OpenSpec proposal/spec/tasks/apply/sync/archive 生命周期完成适配
- B3 owner review、`verification.md` 和 accepted spec sync 形成持久闭环
- CI 自动拒绝活动重复计划、缺失证据、未同步 accepted archive 和本机绝对路径

## Added

- 新增 `apps/lightrag-service` 及其本地部署、测试和 MCP 支持
- 新增 OpenSpec 配置、官方 Codex Skills 和显式 `route-project-change` Skill
- 新增 Harness Engineering 人类说明、项目使用指南和前端 leaf playbook
- 新增 `scripts/check_docs.py` 与对应 CI 门禁

## Changed

- 默认本地启动链路包含 LightRAG HTTP 和 MCP 服务
- 当前 Harness 文档、模板和活动计划统一使用 `.harness`
- B1 保持轻量，B2 按持久协作需要选择 OpenSpec，B3 强制使用 OpenSpec 并在 apply 前完成人工门禁
- accepted change 在 archive 前必须同步 capability specs，rejected/abandoned change 才允许跳过同步

## Fixed

- 修复本地 demo 启动依赖不完整导致知识链路无法直接使用的问题
- 修复 OpenSpec tasks 已完成但验证证据、人工审批或 spec sync 仍可缺失的问题
- 修复活动 `.harness/plans` 与 OpenSpec change 可能重复维护同一变更的问题
- 修复 Graphify、CodeGraph 与本机数据库生成物可能进入提交的问题

- 新设备需保留仓库中的 `.codex/skills/` 与 `openspec/`，并安装 OpenSpec CLI

- 机器本地 Graphify、CodeGraph 和运行数据库不会进入版本控制
