# iam-audit-traceability Specification

## Purpose

定义身份与授权治理变更的语义化审计、治理原因记录、秘密脱敏和可信范围归属。确保用户、项目、成员及服务账号授权变更可追责，同时不记录密码、令牌或未经校验的客户端租户范围。

## Requirements

### Requirement: 受治理的 IAM 修改必须具有语义化审计动作
系统 MUST 为用户创建、资料和状态修改、凭据重置、平台角色分配、项目创建和生命周期修改、管理员恢复、项目接管、成员关系修改以及服务账号项目授权修改产生语义化审计动作。

#### Scenario: 用户平台角色发生变化
- **当** 有权限的超级管理员修改用户平台角色
- **那么** 审计事件标识操作者、目标用户、动作、结果、状态码和服务端租户

#### Scenario: 项目成员修改被拒绝
- **当** 无权限主体尝试修改项目成员关系
- **那么** 系统记录失败的语义化动作，并包含操作者和项目上下文

### Requirement: 项目接管审计必须记录治理原因
项目接管成功后，系统 MUST 将接管原因作为审计 metadata 保存，并同时记录操作者、项目、目标成员关系和结果。

#### Scenario: 项目接管成功
- **当** 超级管理员填写原因并完成项目接管
- **那么** 对应审计事件包含该原因，且不包含任何凭据材料

### Requirement: 审计记录不得包含秘密信息
审计 payload 和 metadata MUST NOT 包含明文密码、密码哈希、API key、刷新令牌、Cookie 或完整 Authorization 请求头。

#### Scenario: 记录凭据重置审计
- **当** 管理员重置用户密码
- **那么** 审计事件记录凭据重置动作和目标，但省略新密码及其哈希

#### Scenario: 创建服务账号令牌
- **当** 系统签发服务账号令牌
- **那么** 审计事件可以标识令牌记录或前缀，但不得包含明文 API key

### Requirement: 审计归属必须使用可信范围
系统 MUST 从服务端解析的上下文和目标资源派生租户及项目审计归属，不得使用未经校验的客户端请求头作为可信来源。

#### Scenario: 客户端伪造租户请求头
- **当** 认证请求包含任意 `x-tenant-id`
- **那么** 审计事件使用服务端默认租户标识
