## ADDED Requirements

### Requirement: 用户治理必须使用细粒度权限
系统 MUST 通过集中式 policy engine，将用户读取、创建、资料修改、状态修改、凭据重置、平台角色分配和超级管理员管理作为相互独立的权限进行校验。

#### Scenario: 平台操作员创建无平台角色用户
- **当** 活动平台操作员创建用户，未指定任何平台角色，并提交管理员设置的有效初始密码
- **那么** 系统创建该用户，允许其使用该密码正常登录，且不授予平台角色

#### Scenario: 平台操作员尝试分配平台角色
- **当** 平台操作员在创建或修改用户时指定任意平台角色
- **那么** 系统拒绝角色分配

#### Scenario: 平台只读者尝试修改用户
- **当** 平台只读者尝试创建、修改、停用、重置或分配用户角色
- **那么** 系统拒绝请求

### Requirement: 超级管理员控制平台角色
系统 MUST 只允许平台超级管理员分配或移除平台角色；修改任何现有超级管理员也必须由平台超级管理员执行。

#### Scenario: 超级管理员授予操作员角色
- **当** 超级管理员为活动普通用户分配 `platform_operator`
- **那么** 系统持久化该角色，且用户后续授权反映新角色

#### Scenario: 操作员尝试修改超级管理员
- **当** 平台操作员尝试修改现有超级管理员的资料、状态、密码或角色
- **那么** 系统拒绝请求

### Requirement: 保护最后一个活动超级管理员
系统 MUST 阻止任何会导致平台不存在活动超级管理员的操作。

#### Scenario: 停用或降级最后一个活动超级管理员
- **当** 更新会停用最后一个活动超级管理员，或移除其超级管理员角色
- **那么** 系统拒绝更新并保留原账号状态

### Requirement: 部署实例只有一个服务端租户
全部用户和项目 MUST 运行在服务端默认租户中。客户端提交的租户标识不得影响授权、数据库过滤、下游转发或审计归属。

#### Scenario: 认证请求提交其他租户请求头
- **当** 客户端提交任意 `x-tenant-id`
- **那么** 系统在信任判断中忽略该值，并在需要租户标识时使用服务端默认租户

#### Scenario: 展示用户管理页面
- **当** 有权限的管理员打开用户管理页面
- **那么** 页面不展示租户选择器或租户管理流程
